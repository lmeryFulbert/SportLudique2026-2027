    Quiz — Git, GitHub et MkDocs

    #

    Quelle affirmation décrit correctement Git et GitHub ?

    Git fonctionne indépendamment de GitHub. Le dépôt local possède notamment son propre historique.

    #

    Vous perdez votre connexion Internet. Quelle opération reste possible ?

    Un commit est créé dans le dépôt Git local. Cette opération ne nécessite donc pas de connexion à GitHub.

    #

    Vous venez de modifier le fichier docs/reseau.md. Quelle commande permet de sélectionner cette modification pour le prochain commit ?

    git add ajoute la modification à la zone de préparation du prochain commit.

    #

    Quelle succession correspond au cycle Git utilisé dans le projet ?

    git add prépare les modifications, git commit les enregistre dans l'historique local et git push transmet les commits au dépôt distant.

    #

    Vous exécutez :

    git commit -m "Ajout documentation DNS"

    Le commit apparaît-il immédiatement sur GitHub ?

    git commit agit sur le dépôt local. Il faut ensuite utiliser git push pour envoyer le commit vers le dépôt distant.

    #

    Un membre de votre groupe a travaillé sur le projet et envoyé ses modifications sur GitHub. Que devriez-vous faire avant de commencer votre propre travail ?

    git pull permet de récupérer les modifications présentes sur le dépôt distant avant de commencer à travailler.

    #

    Pourquoi travailler dans une branche plutôt que directement dans main ?

    Une branche permet de développer ou modifier une partie du projet sans affecter immédiatement la version principale.

    #

    Vous avez terminé votre travail dans la branche documentation-supervision. Quelle étape permet normalement de proposer son intégration dans main ?

    La Pull Request permet de proposer une modification, de la relire et éventuellement de la corriger avant son intégration dans main.

    #

    Quel est l'intérêt principal d'une Pull Request ?

    Une Pull Request permet notamment de visualiser les changements, d'échanger dessus et de les valider avant le merge.

    #

    Dans un projet MkDocs classique, où se trouvent principalement les pages de documentation ?

    Le dossier docs/ contient les fichiers Markdown constituant le contenu du site.

    #

    Quel est principalement le rôle du fichier mkdocs.yml ?

    mkdocs.yml permet notamment de définir le thème, les plugins, les extensions et différentes options du site.

    #

    Vous venez de modifier un tableau Markdown. Pourquoi est-il utile d'exécuter mkdocs serve avant d'envoyer vos modifications ?

    Un fichier Markdown peut être syntaxiquement valide tout en produisant un rendu différent de celui attendu. Tester localement permet de le vérifier.

    #

    Vous trouvez ceci dans un fichier du dépôt :

    api_token = "ghp_xxxxxxxxxxxxxxxxx"

    Quelle est la bonne réaction ?

    Un mot de passe, un token ou une clé privée ne doit pas être stocké dans le dépôt Git. Une branche différente ne constitue pas une protection.

    #

    Vous avez créé une paire de clés SSH avec les fichiers id_ed25519 et id_ed25519.pub. Lequel peut être transmis à GitHub ?

    Le fichier .pub contient la clé publique. La clé privée id_ed25519 doit rester secrète.

    #

    Une modification vient d'être fusionnée dans main. Quelle chaîne correspond au principe de publication automatique utilisé avec MkDocs et GitHub Pages ?

    GitHub Actions peut exécuter automatiquement la construction du site avec MkDocs puis permettre sa publication avec GitHub Pages.

    Diagnostic

    #

    Vous avez modifié un fichier, exécuté git add puis git commit. Sur GitHub, aucune modification n'apparaît. Quelle est l'explication la plus probable ?

    Le commit existe dans le dépôt local. Tant qu'il n'est pas envoyé avec git push, GitHub ne peut pas le voir.

    #

    Votre collègue vous affirme avoir envoyé ses modifications sur GitHub. Sur votre ordinateur, vous voyez toujours l'ancienne version des fichiers. Quelle action est la plus logique ?

    Votre dépôt local ne se synchronise pas automatiquement avec GitHub. git pull permet de récupérer les modifications distantes.

    #

    Votre fichier Markdown semble correct dans votre éditeur, mais le rendu du site est incorrect. Quelle est la meilleure démarche ?

    mkdocs serve permet de tester le site localement et facilite le diagnostic avant publication.
